# Primitives

> Single inventory of this single-package project, in the project root. Status is `confirmed` when the implementation was read and `inferred` when only a reference, a usage or a plan was seen; `pending` follows the status while the code is not on the integration branch.

## image core

`src/core/pipeline.ts` composes these pieces into the stages that the worker and the CLI both call, and its `Source` keeps the edge profiles of one image for every fit; it is composition, not a primitive.

- **`RasterImage`**, `src/core/types.ts`, confirmed, pending
  The single in-memory image format. Contract: `{ width: number; height: number; data: Uint8ClampedArray }`, RGBA8, straight alpha (not premultiplied), row-major.
  Consumers: 7 (`png.ts`, `edge-profile.ts`, `cells.ts`, `sprite.ts`, `pipeline.ts`, `worker.ts` in `src/core`, plus `src/cli/preview.ts`).
- **`decodeRaster` / `decodeImage` / `encodePng`**, `src/core/png.ts`, confirmed, pending
  The only PNG codec. Contract: `decodeRaster(bytes: Uint8Array): RasterImage` (checks only the PNG signature and `PARAMS.limits.maxPixels`), `validateImage(image: RasterImage): RasterImage` (adds the `too-small` and `empty-image` checks), `decodeImage(bytes: Uint8Array): RasterImage` = `validateImage(decodeRaster(bytes))`, `isPng(bytes: Uint8Array): boolean`, `encodePng(image: RasterImage): Uint8Array` (always 8-bit RGBA, the same input gives the same bytes); every PNG color type and bit depth decodes to RGBA8. JPEG and WebP do not pass here: `src/core/worker.ts` decodes them with `createImageBitmap` and `OffscreenCanvas` and validates them through `sourceFromImage`. The CLI reads sprite files with `decodeRaster`, so the size and empty checks do not apply to them.
  Consumers: 5 (`pipeline.ts`, `worker.ts` `isPng`, `cli/clean.ts` `encodePng`, `cli/edit.ts` `decodeRaster`, `cli/files.ts` `decodeRaster` and `isPng`).
- **`computeProfiles` / `EdgeProfiles`**, `src/core/edge-profile.ts`, confirmed, pending
  The edge evidence per axis and the opaque color count, the single input of every grid decision. Contract: `computeProfiles(image: RasterImage): EdgeProfiles`, `EdgeProfiles = { x: AxisEdges; y: AxisEdges; colorCount: number }`, `AxisEdges = { length; profile: Float64Array; peaks: Float64Array; peakWeight; effectiveCount; sharpShare }`, `quantile(values: ArrayLike<number>, q: number): number`; `profile[i]` is the bound at position i+1 (`length - 1` entries), and `peaks` holds the sub-pixel edge positions in bins of `1 / PARAMS.edges.binsPerPixel` source pixel. Edge energy uses premultiplied RGBA, only inside this file. `colorCount` stops at `PARAMS.pitch.nativeMaxColors + 1`, so it is not an exact count.
  Consumers: 4 (`pipeline.ts` `computeProfiles`, `grid.ts`, `pitch.ts` `AxisEdges`, `elastic.ts` `quantile`).
- **`detectPeriods` / `refineSquare` / `refinePeriod` / `measurePeriod` / `phaseOffset`**, `src/core/pitch.ts`, confirmed, pending
  Turns the sub-pixel edge peaks into a fractional period and a phase, with one joint square period for both axes by default. Contract: `detectPeriods(xs: AxisEdges[], ys: AxisEdges[]): SquareFit | null`, `refineSquare(x: AxisEdges, y: AxisEdges, prior: number, window?: { low: number; high: number }): SquareFit`, `refinePeriod(edges: AxisEdges, prior: number, window?: { low: number; high: number }): PeriodResult`, `measurePeriod(edges: AxisEdges, period: number): PeriodResult`, `phaseOffset(edges: AxisEdges, p: number): number` in [0, p), with `SquareFit = { x; y; period; score; prominence; notes: HarmonicNote[] }` and `PeriodResult = { period; coherence; significance; notes }`. The joint score combines both axes, and an axis leaves the joint period only within `PARAMS.pitch.squareSlack` and with enough significance; with more than one image, x = y. `detectPeriods` returns `null` when no period scores above 0. Without `window`, a refinement can move to a harmonic; with `window`, it stays inside the window.
  Consumers: 2 (`grid.ts`; `cli/process.ts` uses `detectPeriods` for the shared period of an image set).
- **`fitBoundaries`**, `src/core/elastic.ts`, confirmed, pending
  Puts irregular cell bounds on the drawn edges when the cell size drifts. Contract: `fitBoundaries(strength: Float64Array, length: number, period: number): Float64Array`, `edgeStrength(profile: Float64Array, length: number): Float64Array` (`length + 1` entries, entry c is the bound between pixel c-1 and pixel c), `capture(strength: Float64Array, bounds: Float64Array): number`, `keepInside(bounds: Float64Array, length: number): Float64Array`.
  Consumers: 1 (`grid.ts`).
- **`CellGrid` / `GridFit` / `fitGrid`**, `src/core/grid.ts` (types in `src/core/types.ts`), confirmed, pending
  The grid contract that calibration, sampling and export assume, and the single function that fits it. Contract: `fitGrid(width: number, height: number, edges: EdgeProfiles, selection: Selection | null, options: GridOptions, extras: FitExtras = {}): GridFit`; `CellGrid = { x: Float64Array; y: Float64Array }`, n+1 ascending bounds per axis in source pixels, and a bound can lie outside the image; `GridFit = { grid; cols; rows; axes: { x: AxisFit; y: AxisFit }; quality: 1 | 2 | 3; notes: GridNote[] }`, `AxisFit = { period; offset; coherence; adapted }`; `Selection = { x; y; w; h }` is the box over ONE art pixel, in float source pixels; `GridOptions = { elastic: 'auto' | 'on' | 'off'; fixedPeriod?: { x; y }; nudge?: { x; y } }`; `FitExtras = { sharedPeriod?; nonSquare?; typedSize? }`. The fit uses one square period by default; separate periods per axis come only from `fixedPeriod`, a box whose sides differ by more than `PARAMS.pitch.squareTolerance`, or `nonSquare`. `fixedPeriod` is used as given, without refinement. A nonzero `nudge` forces elastic off. Weak evidence or a tiny period gives native mode (period 1, offset 0). It throws `CoreError('too-many-cells')` above `PARAMS.limits.maxCells`.
  Consumers: `fitGrid` 1 (`pipeline.ts`); `GridFit` 9 (`engine.ts`, `state.svelte.ts`, `protocol.ts`, `worker.ts`, `pipeline.ts`, `cli/preview.ts`, `cli/process.ts`, `grid-scene.ts`, `GridScreen.svelte`).
- **`sampleCells` / `alignedImage`**, `src/core/cells.ts`, confirmed, pending
  One flat color per tile, from the largest color area of the cell core. Contract: `sampleCells(image: RasterImage, grid: CellGrid, onProgress?: (ratio: number) => void): Sprite`; `alignedBlock(fitPeriodX: number, fitPeriodY: number, cols: number, rows: number): number` and `alignedImage(image: RasterImage, grid: CellGrid, block: number): RasterImage` draw each cell as a uniform square block for the before/after comparison. The band at the border of each cell does not vote, a tile with a large transparent share becomes `TRANSPARENT`, and the tile color is the per-channel weighted median of the winning area.
  Consumers: 1 (`pipeline.ts`).
- **`clusterColors` / `mergePalette`**, `src/core/palette.ts`, confirmed, pending
  The single color-merge rule: OKLab clustering that makes near-identical tile colors identical. Contract: `clusterColors(entries: ColorCount[], options: MergeOptions, refinePasses?: number): Map<number, number>`, with entries sorted by count desc, then value asc (the order of `listPalette`), and an identity map when `strength <= 0` and `maxColors` is not exceeded; `MergeOptions = { strength: number; maxColors?: number }` (`src/core/protocol.ts`). Compositions in the same file: `mergePalette(raw: Sprite, options: MergeOptions): { sprite: Sprite; palette: Uint32Array }`, `mergeShared(raws: Sprite[], options: MergeOptions): Sprite[]` (one palette for an image set), `mapToPalette(sprite: Sprite, palette: ArrayLike<number>): Sprite` (nearest OKLab color, lowest index on ties), `applyColorMap` and `paletteOf`. `TRANSPARENT` is never remapped. When `maxColors` is exceeded, the heavier cluster keeps its color.
  Consumers: `clusterColors` 0 outside the file; `mergePalette` 2 (`pipeline.ts`, `cli/process.ts`); `mergeShared` 1 (`cli/process.ts`); `mapToPalette` 1 (`cli/operations.ts`).
- **`color`**, `src/core/color.ts`, confirmed, pending
  The packed color format, its channel accessors, hex text and OKLab distance. Contract: `TRANSPARENT = 0`, `pack(r: number, g: number, b: number): number`, `red(color)`, `green(color)`, `blue(color)`, `alpha(color)`, `toHex(color): string` (lowercase `#rrggbb`, not for `TRANSPARENT`), `fromHex(text: string): number | null` (`#rgb` or `#rrggbb`, `#` optional), `toOklab(color): [number, number, number]`, `deltaOk(a, b): number`, `lightness(color): number`. The layout is `0xAABBGGRR`, so a `Uint32Array` over RGBA bytes reads it directly on little-endian. `pack` always sets alpha to 255: a packed color is `TRANSPARENT` or fully opaque, never partly transparent. `deltaOk` and `lightness` have no consumer.
  Consumers: >=13 (`cells.ts`, `palette.ts`, `sprite.ts`; `cli/operations.ts`, `cli/values.ts`, `cli/files.ts`, `cli/process.ts`; `state.svelte.ts`; `CleanScreen.svelte`, `clean-scene.ts`, `stage-renderer.ts`, `PalettePanel.svelte`, `ExportDialog.svelte`).
- **`PARAMS`**, `src/core/params.ts`, confirmed, pending
  The home of the calibrated algorithm constants; game-feel constants are in [[PRIMITIVES#TUNING]]. Contract: `PARAMS = { limits, edges, pitch, elastic, cells, palette, background, preview } as const`; `PARAMS.limits` holds the input and export limits. Some core modules still keep local constants (`edge-profile.ts`, `pitch.ts`, `elastic.ts`, `grid.ts`, `palette.ts`, `sprite.ts`).
  Consumers: 15 (9 `src/core` modules, `cli/values.ts`, `cli/preview.ts`, `cli/clean.ts`, `cli/help.ts`, `state.svelte.ts`, `ExportDialog.svelte`).
- **`CoreError`**, `src/core/errors.ts` (codes in `src/core/protocol.ts`), confirmed, pending
  An expected failure with a stable code, shared by the worker reply, the CLI exit and the UI error text. Contract: `class CoreError extends Error { readonly code: ErrorCode }`, `new CoreError(code: ErrorCode, message: string)`, `errorCode(error: unknown): ErrorCode` (`'internal'` for any other error), `errorMessage(error: unknown): string`; the `ErrorCode` union in `src/core/protocol.ts` lists the codes. The worker turns it into `{ ok: false, error, detail }`, and `cli/errors.ts` turns it into `CliError` through `toCliError`. A new code needs an `error.<code>` key in `src/app/i18n.ts`, because `app.errorText` builds that key from the code.
  Consumers: 5 (`png.ts`, `grid.ts`, `pipeline.ts`, `worker.ts`, `cli/errors.ts`).

## sprite edit

`src/cli/operations.ts` (`Operation`, `applyOperations`) composes these operations for the CLI; the app applies the same operations through `EditSession` and `CleanScreen.svelte`. It is composition, not a primitive.

- **`Sprite`**, `src/core/types.ts`, confirmed, pending
  The clean tile result that the engine, the editor, the stage, the CLI and the export share. Contract: `{ cols: number; rows: number; pixels: Uint32Array }`, one packed color per tile ([[PRIMITIVES#color]]), row-major.
  Consumers: 12 (`cells.ts`, `palette.ts`, `sprite.ts`, `pipeline.ts`, `protocol.ts`, `worker.ts`; `engine.ts`, `edit-session.ts`, `state.svelte.ts`; `cli/operations.ts`, `cli/process.ts`; `clean-scene.ts`).
- **`floodRegion` / `borderBackground` / `indicesOfColor` / `listPalette` / `lineTiles` / `scaleNearest` / `spriteFromRaster`**, `src/core/sprite.ts`, confirmed, pending
  Tile-level operations on a `Sprite`: region and color selection, background detection, lines, palette listing, integer upscale and raster import. Contract: `floodRegion(sprite: Sprite, start: number): { indices: Int32Array; distance: Uint16Array }` (4-connected on the exact color, `distance` in steps, empty for an invalid start), `borderBackground(sprite: Sprite): Int32Array` (sorted; empty when half or more of the border is transparent or no border color has enough share; several border colors flood together, for a fake checkerboard), `indicesOfColor(pixels: Uint32Array, color: number): Int32Array`, `listPalette(pixels: Uint32Array): Array<{ color: number; count: number }>` (no `TRANSPARENT`, count desc, then value asc), `lineTiles(x0: number, y0: number, x1: number, y1: number): Int32Array` (flat x,y pairs, both ends included), `scaleNearest(sprite: Sprite, scale: number): RasterImage`, `spriteFromRaster(image: RasterImage, blockSize = 1): Sprite` (block center, alpha below 128 becomes `TRANSPARENT`). `exportSprite` in `src/core/pipeline.ts` checks the export limit before `scaleNearest`. `src/cli/files.ts` repeats the `spriteFromRaster` alpha rule inline.
  Consumers: >=8 (`palette.ts`, `pipeline.ts`, `edit-session.ts`, `CleanScreen.svelte`, `cli/operations.ts`, `cli/process.ts`, `cli/files.ts`, `cli/edit.ts`).
- **`EditSession`**, `src/app/edit-session.ts`, confirmed, pending
  Keeps the user edits as an overlay over a base sprite, with undo and redo. Contract: `setBase(sprite: Sprite): void`, `clear(): void`, `apply(indices: Int32Array, colors: number | Uint32Array): Int32Array`, `undo(): Int32Array | null`, `redo(): Int32Array | null`, `swapColor(from: number, to: number): Int32Array`, `composed(): Sprite`, getters `canUndo`, `canRedo`, `hasEdits`, `hasBase`; each edit returns the changed indices, and an edit that changes nothing returns an empty array and adds no undo step. `setBase` with the same `cols` and `rows` keeps the overlay and the history, so edits stay after a palette merge; other dimensions reset everything. `composed()` returns the same cached object until the next change, so callers must not mutate it. `swapColor` is one undo step.
  Consumers: 1 importer (`state.svelte.ts`); `CleanScreen.svelte` and `ExportDialog.svelte` use it through `app.session`.

## worker bridge

- **`EngineRequest` / `EngineReply` / `EngineEvent`**, `src/core/protocol.ts` (served by `src/core/worker.ts`), confirmed, pending
  The message contract between the app and the core worker. Contract: every message carries `id: number`; requests are `load { bytes: ArrayBuffer }`, `fit { selection: Selection | null; options: GridOptions }`, `clean { merge: MergeOptions }`, `merge { merge: MergeOptions }` and `export { sprite: Sprite; scale: number }`; a reply is `{ ok: true; type }` with the payload of its type (`load`: `width`, `height`, `bitmap: ImageBitmap`, `fit`; `fit`: `fit`; `clean`: `sprite`, `palette`, `aligned: ImageBitmap`; `merge`: `sprite`, `palette`; `export`: `png: ArrayBuffer`) or `{ ok: false; error: ErrorCode; detail?: string }`; `EngineEvent = { id; type: 'progress'; stage: Stage; ratio }`; `WorkerMessage = EngineReply | EngineEvent`. The protocol has no drop rule; [[PRIMITIVES#CleanEngine]] drops stale replies. The worker keeps the loaded image and the last raw sample, runs requests one at a time in arrival order, and transfers the sprite, palette, bitmap and PNG buffers; `fit` discards the raw sample, and `export` without an image fails with `no-image`.
  Consumers: >=7 (messages: `worker.ts`, `engine.ts`; `ErrorCode`: `errors.ts`; `MergeOptions`: `palette.ts`, `pipeline.ts`; `Stage`: `state.svelte.ts`, `ProgressPill.svelte`).
- **`CleanEngine`**, `src/app/engine.ts`, confirmed, pending
  The only door from the app to the core worker, as promise calls. Contract: `load(bytes: ArrayBuffer): Promise<LoadResult>`, `fit(selection: Selection | null, options: GridOptions, call?: { debounce?: boolean }): Promise<GridFit | null>`, `clean(merge: MergeOptions): Promise<CleanResult>`, `merge(merge: MergeOptions, call?: { debounce?: boolean }): Promise<MergeResult | null>`, `exportPng(sprite: Sprite, scale: number): Promise<Uint8Array>`, `onProgress(listener: (stage: Stage, ratio: number, id: number) => void): () => void`; a failed call rejects with `EngineError { code: ErrorCode; detail }`. Only `fit` and `merge` are latest-wins: a stale or superseded call resolves `null` and does not reject, so callers must handle `null`. `clean` makes an in-flight `merge` stale. `load` transfers `bytes`, so the caller's buffer becomes detached; `exportPng` copies the pixels first. A worker crash rejects every pending call with `internal`, and the next worker has no image, so the next call fails with `no-image`. The worker starts on the first call.
  Consumers: 2 (`state.svelte.ts` `CleanEngine` and `EngineError`; `ExportDialog.svelte` `EngineError` and `app.engine.exportPng`).

## ui

- **`Camera`**, `src/ui/camera.ts`, confirmed, pending
  Zoom and pan math between stage screen space (CSS px) and content space. Contract: `setViewport(width, height)`, `setContent(width, height, maxZoom)`, `fitZoom(): number`, `fit(zoom?)`, `zoomAt(screenX, screenY, factor, animate = true)`, `zoomAtCenter(factor)`, `step(dt): boolean`, `panBy(dx, dy)`, `screenToImage(screenX, screenY): Point`, `imageToScreen(x, y): Point`, `tileAt(screenX, screenY): Tile | null`, fields `zoom`, `panX`, `panY`; the file also exports `clamp`, `Point` and `Tile`. Content space is source pixels on the grid screen and tiles on the clean screen, so "image" in the method names means content units. An animated zoom moves only when `step(dt)` runs each frame, and `fit` cancels it. The pan always keeps part of the content visible. `tileAt` has no consumer: `CleanScreen.svelte` computes the tile from `StagePointer.ix` and `iy`.
  Consumers: 7 (`Stage.svelte` owns the instance; `stage-renderer.ts`, `grid-scene.ts`, `clean-scene.ts`, `CleanScreen.svelte`, `GridScreen.svelte` and `state.svelte.ts` use its types or `clamp`).
- **`Stage`**, `src/ui/Stage.svelte`, confirmed, pending
  The single canvas viewport: it owns the stage and effects canvases, the `Camera`, the `ParticleField`, the frame loop and all pointer, wheel and key input, and shows one [[PRIMITIVES#Scene]]. Contract: props `scene: Scene`, `label: string`, `cursor?: string`, `onprimarydown?: (p: StagePointer) => boolean | 'pan' | void`, `onprimarymove?`, `onprimaryup?` and `onaltclick?` (`(p: StagePointer) => void`), `onhover?: (p: StagePointer | null) => void`, `onviewchange?: () => void`, `children?: Snippet` (overlay above the canvases); instance methods `invalidate()`, `fitView()`, `zoomBy(factor)`. `onprimarydown` returns `false` to ignore the press or `'pan'` to pan; the middle button and space with the left button pan; the right button calls `onaltclick` unless it moves past a small threshold, and then it pans. Each frame runs `camera.step`, `particles.step`, `scene.draw(ctx, fx, now)` and `particles.draw(fx)`, with the DPR transform and no image smoothing, so scenes draw in CSS px and particles draw above the scene effects. Until the user zooms or pans, a resize fits the view again. Reduced motion disables the particles and sets `host.reducedMotion`. It publishes `app.stage = { camera, canvas }` for the dev hook.
  Consumers: 2 (`GridScreen.svelte`, `CleanScreen.svelte`).
- **`Scene` / `StageHost` / `StagePointer`**, `src/ui/stage-renderer.ts`, confirmed, pending
  The contract between `Stage` and the screen that draws in it, plus the shared stage draw helpers.

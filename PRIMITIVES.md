# Primitives

> Single inventory of this single-package project, in the project root. Status is `confirmed` when the implementation was read and `inferred` when only a reference, a usage or a plan was seen; `pending` follows the status while the code is not on the integration branch.

## image core

`src/core/pipeline.ts` composes these pieces into the stages that the worker, the CLI and `SetExportDialog.svelte` call, and its `Source` keeps the edge profiles of one image for every fit; it is composition, not a primitive, except the set grid rules in [[PRIMITIVES#SetGrid]] and the reference rule in [[PRIMITIVES#matchColors]]. Its `exportSprite(sprite: Sprite, options: { optimize?: boolean } = {}): Uint8Array` is the single PNG export door: it throws `CoreError('too-large')` when a side is above `PARAMS.limits.maxExportSide`, converts at 1x with `spriteToRaster`, and encodes with `encodePngSmallest` when `optimize` is set, otherwise with `encodePng`; its consumers are `worker.ts`, `cli/clean.ts`, `cli/edit.ts`, `state.svelte.ts` (dev hook) and `SetExportDialog.svelte` (main thread).

- **`RasterImage`**, `src/core/types.ts`, confirmed
  The single in-memory image format. Contract: `{ width: number; height: number; data: Uint8ClampedArray }`, RGBA8, straight alpha (not premultiplied), row-major.
  Consumers: 7 (`png.ts`, `edge-profile.ts`, `cells.ts`, `sprite.ts`, `pipeline.ts`, `worker.ts` in `src/core`, plus `src/cli/preview.ts`).
- **`decodeRaster` / `decodeImage` / `encodePng` / `encodePngSmallest`**, `src/core/png.ts`, confirmed
  The only PNG codec. Contract: `decodeRaster(bytes: Uint8Array): RasterImage` (checks only the PNG signature and `PARAMS.limits.maxPixels`), `validateImage(image: RasterImage): RasterImage` (adds the `too-small` and `empty-image` checks), `decodeImage(bytes: Uint8Array): RasterImage` = `validateImage(decodeRaster(bytes))`, `isPng(bytes: Uint8Array): boolean`, `encodePng(image: RasterImage): Uint8Array` (always 8-bit RGBA, the same input gives the same bytes), `encodePngSmallest(image: RasterImage): Uint8Array` (lossless and deterministic: the smallest of fixed candidates, which are indexed with the lowest bit depth when the image has at most 256 RGBA colors, RGB when every pixel is opaque, and RGBA; on a tie it keeps the `encodePng` output); every PNG color type and bit depth decodes to RGBA8. The color key of `encodePngSmallest` is the full RGBA value, so pixels with alpha 0 and different RGB count as different colors. JPEG and WebP do not pass here: `src/core/worker.ts` decodes them with `createImageBitmap` and `OffscreenCanvas` and validates them through `sourceFromImage`. The CLI reads sprite files with `decodeRaster`, so the size and empty checks do not apply to them. The CLI accepts PNG input only: `readInput` (`src/cli/files.ts`) rejects other bytes with `CliError('not-an-image')`.
  Consumers: 5 (`pipeline.ts` `decodeImage`, `validateImage`, `encodePng`, `encodePngSmallest`; `worker.ts` `isPng`; `cli/clean.ts` `encodePng` for the grid preview; `cli/edit.ts` `decodeRaster`; `cli/files.ts` `decodeRaster` and `isPng`).
- **`computeProfiles` / `EdgeProfiles`**, `src/core/edge-profile.ts`, confirmed
  The edge evidence per axis and the opaque color count, the single input of every grid decision. Contract: `computeProfiles(image: RasterImage): EdgeProfiles`, `EdgeProfiles = { x: AxisEdges; y: AxisEdges; colorCount: number }`, `AxisEdges = { length; profile: Float64Array; peaks: Float64Array; peakWeight; effectiveCount; sharpShare }`, `quantile(values: ArrayLike<number>, q: number): number`; `profile[i]` is the bound at position i+1 (`length - 1` entries), and `peaks` holds the sub-pixel edge positions in bins of `1 / PARAMS.edges.binsPerPixel` source pixel. Edge energy uses premultiplied RGBA, only inside this file. `colorCount` counts the distinct RGB values of the pixels with alpha 128 or more and stops at `PARAMS.pitch.nativeMaxColors + 1`, so it is not an exact count.
  Consumers: 5 (`pipeline.ts` `computeProfiles`, `grid.ts`, `pitch.ts` `AxisEdges`, `elastic.ts` and `src/ui/grid-lines.ts` `quantile`).
- **`detectPeriods` / `refineSquare` / `refinePeriod` / `measurePeriod` / `phaseOffset`**, `src/core/pitch.ts`, confirmed
  Turns the sub-pixel edge peaks into a fractional period and a phase, with one joint square period for both axes by default. Contract: `detectPeriods(xs: AxisEdges[], ys: AxisEdges[]): SquareFit | null`, `refineSquare(x: AxisEdges, y: AxisEdges, prior: number, window?: { low: number; high: number }): SquareFit`, `refinePeriod(edges: AxisEdges, prior: number, window?: { low: number; high: number }): PeriodResult`, `measurePeriod(edges: AxisEdges, period: number): PeriodResult`, `phaseOffset(edges: AxisEdges, p: number): number` in [0, p), with `SquareFit = { x; y; period; score; prominence; notes: HarmonicNote[] }` and `PeriodResult = { period; coherence; significance; notes }`. The joint score combines both axes, and an axis leaves the joint period only within `PARAMS.pitch.squareSlack` and with enough significance; with more than one image, x = y. `detectPeriods` returns `null` when no period scores above 0. Without `window`, a refinement can move to a harmonic; with `window`, it stays inside the window.
  Consumers: 2 (`grid.ts`; `pipeline.ts` uses `detectPeriods` in `sharedPeriodOf`).
- **`fitBoundaries` / `fitAnchoredBoundaries`**, `src/core/elastic.ts`, confirmed
  Puts irregular cell bounds on the drawn edges when the cell size drifts. Contract: `fitBoundaries(strength: Float64Array, length: number, period: number): Float64Array` (free fit, then `keepInside`), `fitAnchoredBoundaries(strength: Float64Array, length: number, period: number, low: number, high: number): Float64Array` (keeps the cell `[low, high]` exactly and fits each side of it, then `keepInside`), `fitBoundariesFrom(strength: Float64Array, length: number, period: number, start: number): Float64Array` (the first bound is exactly `start`; used only inside the file), `edgeStrength(profile: Float64Array, length: number): Float64Array` (`length + 1` entries, entry c is the bound between pixel c-1 and pixel c), `capture(strength: Float64Array, bounds: Float64Array): number`, `keepInside(bounds: Float64Array, length: number): Float64Array` (the run of cells whose center is inside `[0, length)`; the input unchanged when no cell qualifies).
  Consumers: 1 (`grid.ts`).
- **`CellGrid` / `GridFit` / `fitGrid` / `manualGridFit`**, `src/core/grid.ts` (types in `src/core/types.ts`), confirmed
  The grid contract that calibration, sampling and export assume, and the functions that fit it from the edges or take it from the user. Contract: `fitGrid(width: number, height: number, edges: EdgeProfiles, selection: Selection | null, options: GridOptions, extras: FitExtras = {}): GridFit`, `manualGridFit(width: number, height: number, edges: EdgeProfiles, grid: CellGrid): GridFit`; `CellGrid = { x: Float64Array; y: Float64Array }`, n+1 ascending bounds per axis in source pixels, and a bound can lie outside the image; `GridFit = { grid; cols; rows; axes: { x: AxisFit; y: AxisFit }; quality: 1 | 2 | 3; notes: GridNote[]; suggestion?: { period: { x; y }; kind: 'larger' | 'smaller' } }`, `AxisFit = { period; offset; coherence; adapted }` (`offset` includes the nudge), and `GridNote` includes `'manual'`; `Selection = { x; y; w; h }` is the box over ONE art pixel, in float source pixels; `GridOptions = { elastic: 'auto' | 'on' | 'off'; fixedPeriod?: { x; y }; nudge?: { x; y } }`; `FitExtras = { sharedPeriod?; nonSquare?; typedSize? }`; `translateBounds(bounds: Float64Array, shift: number, period: number, length: number): Float64Array` (shifts every bound, adds whole cells of `period` at both ends and drops the cells outside; used only inside the file). The fit uses one square period by default; separate periods per axis come only from `fixedPeriod`, a box whose sides differ by more than `PARAMS.pitch.squareTolerance`, `nonSquare`, or a weak box that is measured per axis. `fixedPeriod` is used as given, without refinement. A drawn box keeps its period within `PARAMS.pitch.boxWindow` (a typed size within `PARAMS.pitch.hintWindow`), with no harmonic correction and no harmonic note; when the edges point to another size, the fit of a drawn box still keeps the box size and sets `suggestion`, never for `typedSize` or native mode, and the core never applies it. A drawn box is the position anchor: one cell is centered on the box center, also with `fixedPeriod`; with `typedSize` there is no anchor, and the phase comes from the edges. The elastic fit runs with `'on'`, or with `'auto'` at quality `PARAMS.elastic.minQuality` and period `PARAMS.elastic.minPeriod` or more, and stays only with `'on'` or a capture gain of `minGain` (`countChangeGain` when the cell count changes). With a box, `'auto'` keeps it only when a free cell is centered within `anchorTolerance` source pixels or `anchorShare` of the period of the box center, and then `fitAnchoredBoundaries` keeps the box cell exactly. Under a period that the user set in the app (`fixedPeriod` or a box, without `typedSize`), the elastic fit may change the cell count of an axis by at most `userCountSlack` cells or `userCountShare` of the count, else the regular grid stays; the CLI passes `typedSize`, so the limit does not apply to it. `nudge` moves the whole fitted grid as one rigid body: the grid, regular or elastic, is decided as with no nudge and then shifted (an elastic grid through `translateBounds`), so a nudge does not turn the elastic fit off. Native mode (period 1, offset 0, note `'native-resolution'`) comes only from a `fixedPeriod` or a box below `PARAMS.pitch.nativeBelow` on both axes, or from an automatic fit with weak evidence and one of these: no detected period, a sharp-edge share of `PARAMS.pitch.nativeSharpShare` or more on both axes, or `colorCount` at most `PARAMS.pitch.nativeMaxColors`. In the automatic fit, a strong detected period never gives native mode, so the `'native-resolution'` note does not tell that an image is already clean pixel art. Both fits throw `CoreError('too-many-cells')` above `PARAMS.limits.maxCells`. `manualGridFit` takes the user lines as given and throws `CoreError('internal')` unless each axis has at least 2 finite lines, a spacing of `PARAMS.manualGrid.minSpacing` or more (so the lines ascend), every cell center inside the image and each end strip smaller than its end cell; its period is the median spacing and its note is `'manual'`. [[PRIMITIVES#moveLine]] repeats these checks on the UI side. `regularBounds(length, period, offset)` has no importer; `src/ui/grid-scene.ts` has its own `regularBounds(offset, period, length)` with another parameter order and range.
  Consumers: `fitGrid` and `manualGridFit` 1 (`pipeline.ts`); `GridFit` 11 (`engine.ts`, `worker.ts`, `protocol.ts`, `pipeline.ts`, `state.svelte.ts`, `image-set.svelte.ts`, `cli/process.ts`, `cli/preview.ts`, `grid-scene.ts`, `GridScreen.svelte`, `GridAdvanced.svelte`); `CellGrid` 9 outside the file.
- **`SetGrid` / `suggestedSetGrid` / `fitSetSource`**, `src/core/pipeline.ts` (`SetGrid` in `src/core/protocol.ts`), confirmed
  The grid contract of an image set, and the single rule that suggests one shared grid or one grid per image. Contract: `SetGrid = { kind: 'own' } | { kind: 'shared' } | { kind: 'fixed'; period: { x: number; y: number } }`; `checkSetGrid(grid: SetGrid): void` (`CoreError('internal')` for another kind or a period that is not finite and above 0); `sharedPeriodOf(sources: Source[]): { x: number; y: number } | null` (the joint period of `detectPeriods`; `null` for no source); `jointFit(source: Source, shared: { x: number; y: number }): GridFit` (the auto fit with `sharedPeriod`); `fitSetSource(source: Source, grid: SetGrid, own: GridFit, joint: GridFit | null): GridFit` (`own` gives the own fit, `shared` gives the joint fit or the own fit when there is none, `fixed` fits with `fixedPeriod` and elastic `'auto'`, so the phase still comes from the edges); `suggestedSetGrid(fits: Array<{ own: GridFit; joint: GridFit | null }>): 'own' | 'shared'`. `suggestedSetGrid` gives `'shared'` only for 2 or more fits that all have a joint fit, when each own fit of quality 3 is within `PARAMS.set.sharedTolerance` of the joint period on both axes and the lower median image keeps at least `PARAMS.set.minSharedKeep` of its own grid coherence under the joint period.
  Consumers: 2 (`worker.ts` all of them, for `fit-set`; `cli/process.ts` `sharedPeriodOf`).
- **`sampleCells` / `alignedImage`**, `src/core/cells.ts`, confirmed
  One flat color per tile, from the largest color area of the cell core. Contract: `sampleCells(image: RasterImage, grid: CellGrid, onProgress?: (ratio: number) => void): Sprite`; `alignedBlock(fitPeriodX: number, fitPeriodY: number, cols: number, rows: number): number` and `alignedImage(image: RasterImage, grid: CellGrid, block: number): RasterImage` draw each cell as a uniform square block for the before/after comparison. The band at the border of each cell does not vote, a tile with a large transparent share becomes `TRANSPARENT`, and the tile color is the per-channel weighted median of the winning area.
  Consumers: 1 (`pipeline.ts`).
- **`clusterColors` / `mergePalette`**, `src/core/palette.ts`, confirmed
  The single color-merge rule: OKLab clustering that makes near-identical tile colors identical. Contract: `clusterColors(entries: ColorCount[], options: MergeOptions, refinePasses?: number): Map<number, number>`, with `ColorCount = { color: number; count: number }`, entries sorted by count desc, then value asc (the order of `listPalette`), and an identity map when `strength <= 0` and `maxColors` is not exceeded; `MergeOptions = { strength: number; maxColors?: number }` (`src/core/protocol.ts`). Compositions in the same file: `mergePalette(raw: Sprite, options: MergeOptions): { sprite: Sprite; palette: Uint32Array }`, `combinedColors(sprites: readonly Sprite[]): ColorCount[]` (the opaque colors of several sprites with summed counts, in the order of `listPalette`; `combinedPalette` in `src/cli/process.ts` repeats this order without an import, so a change of one needs the same change in the other), `unifyPalettes(own: Sprite[], options: MergeOptions): Sprite[]` (one palette over the `combinedColors` of sprites that already merged their own colors, at `strength` times `PARAMS.palette.sharedFactor`), `mergeShared(raws: Sprite[], options: MergeOptions): Sprite[]` (the own merge of each sprite with `strength` only, then `unifyPalettes`), `mapToPalette(sprite: Sprite, palette: ArrayLike<number>): Sprite` (nearest OKLab color, lowest index on ties), `applyColorMap(sprite: Sprite, map: Map<number, number>): Sprite` (a new sprite; a color without a key stays as it is) and `paletteOf(sprite: Sprite): Uint32Array` (the unique opaque colors in the order of `listPalette`). `TRANSPARENT` is never remapped. When `maxColors` is exceeded, the heavier cluster keeps its color.
  Consumers: 4 files; `clusterColors` 0 outside the file; `mergePalette` 2 (`pipeline.ts`, `cli/process.ts`); `mergeShared` 1 (`cli/process.ts`); `unifyPalettes` 1 outside the file (`image-set.svelte.ts`); `mapToPalette` 1 (`cli/operations.ts` for the `palette` operation of `--palette`); `combinedColors` 2 outside the file (`image-set.svelte.ts`, `cli/process.ts`); `paletteOf` >=1 outside the file (`cli/process.ts`).
- **`matchColors` / `matchToReference` / `referenceTiles` / `referencePalette`**, `src/core/palette.ts` (reference tiles in `src/core/pipeline.ts`), confirmed
  The single rule that gives each color of an image the matching color of a reference image, after the lightness change that the image shares with the reference is taken out. Contract: `matchColors(entries: readonly ColorCount[], reference: readonly ColorCount[]): Map<number, number>`, both lists in the order of `listPalette`; an empty reference gives an identity map, and no entry gives an empty map. A transport plan (an integer min-cost flow) pairs the tile shares of the image colors with the tile shares of the reference colors at the lowest sum of squared OKLab distances, only for pairs nearer than `reach`; one lightness curve, quadratic in L, is fitted to the pairs by least squares, and every color moves along it, at most `reach` per pass, for `passes` passes. A palette with more than `topColors` colors first merges its near colors at `planStrength`, and the plan reads only the `topColors` heaviest colors of each palette. A gate keeps the curve only when the meet score of the two palettes (the pairs nearer than `radius`) rises by more than the share `minGain`; else the map is that of `mapToPalette`. With the curve, each color goes to the nearest reference color in OKLab, lowest index on ties, except that of two reference colors whose distances differ by less than `close`, it takes the one that gets more of its tiles in the plan. The constants are in `PARAMS.palette.reference`. The plan uses integer units and fixed tie rules, so the same input gives the same map. The rule moves only the lightness: `a` and `b` never change, so a tint difference between the image and the reference is not corrected. `matchToReference(sprite: Sprite, reference: readonly ColorCount[]): Sprite` is `applyColorMap` with the map of the `listPalette` of the sprite. The curve is fitted per call, so sprites that must share one map take one `matchColors` over their `combinedColors`, as the set and the CLI `--shared-palette` do; a separate `matchToReference` per sprite can send one color to two reference colors. `ReferenceTiles = { sprite: Sprite; flat: boolean }`; `referenceTiles(source: Source): ReferenceTiles` treats a reference with `colorCount` at most `PARAMS.pitch.nativeMaxColors` as a clean sprite (`flat`, one tile per pixel through `spriteFromRaster`) and samples any other reference on its automatic grid; `referencePalette(reference: ReferenceTiles, merge: MergeOptions): ColorCount[]` merges the colors of a reference that is not flat at `merge.strength`, without `maxColors`, and lists them. `readReference(path: string, strength: number | null): ColorCount[]` (`src/cli/files.ts`) is the CLI door: `clean` and `inspect` pass the `--cleanup` strength, and `edit` passes `null`, which accepts only a flat reference and else throws `CliError('bad-palette')`, as it also does for a reference with no opaque color.
  Consumers: `matchColors` 2 (`image-set.svelte.ts`, `cli/process.ts`); `matchToReference` 3 (`state.svelte.ts`, `cli/operations.ts` for the `reference` operation of `edit --reference`, `cli/process.ts`); `referenceTiles` 2 (`worker.ts` for the `reference` request, `cli/files.ts`); `referencePalette` 2 (`state.svelte.ts`, `cli/files.ts`).
- **`color`**, `src/core/color.ts`, confirmed
  The packed color format, its channel accessors, hex text and OKLab distance. Contract: `TRANSPARENT = 0`, `pack(r: number, g: number, b: number): number`, `red(color)`, `green(color)`, `blue(color)`, `alpha(color)`, `toHex(color): string` (lowercase `#rrggbb`, not for `TRANSPARENT`), `fromHex(text: string): number | null` (`#rgb` or `#rrggbb`, `#` optional), `toOklab(color): [number, number, number]`, `deltaOk(a, b): number`, `lightness(color): number`. The layout is `0xAABBGGRR`, so a `Uint32Array` over RGBA bytes reads it directly on little-endian. `pack` always sets alpha to 255: a packed color is `TRANSPARENT` or fully opaque, never partly transparent. `deltaOk` and `lightness` have no consumer.
  Consumers: 15 (`cells.ts`, `palette.ts`, `sprite.ts`; `cli/operations.ts`, `cli/values.ts`, `cli/files.ts`, `cli/process.ts`; `state.svelte.ts`, `image-set.svelte.ts`; `CleanScreen.svelte`, `clean-scene.ts`, `stage-renderer.ts`, `PalettePanel.svelte`, `ExportDialog.svelte`, `SetExportDialog.svelte`).

Some core modules still keep local constants (`edge-profile.ts`, `pitch.ts`, `elastic.ts`, `grid.ts`, `palette.ts`, `sprite.ts`).
  Consumers: 17 (9 `src/core` modules, `cli/clean.ts`, `cli/help.ts`, `cli/operations.ts`, `cli/values.ts`, `cli/preview.ts`, `state.svelte.ts`, `GridAdvanced.svelte`, `grid-lines.ts`).

## sprite edit

`src/cli/operations.ts` (`Operation`, `applyOperations`, `resizeToHeight`, `cropToOpaque`) composes these operations for the CLI: `resizeToHeight` adds only the `--height` limit error to `heightLimit`, `heightStep` and `resampleSprite`, and `cropToOpaque` wraps `trimSprite` with an error text that names `--no-trim`; the app applies the same operations through `EditSession`, `CleanScreen.svelte` and [[PRIMITIVES#ImageSet]]. It is composition, not a primitive. The CLI commands `clean` and `inspect` parse the same `PIPELINE_OPTIONS` (`src/cli/clean.ts`), so an option added there reaches both commands.

- **`Sprite`**, `src/core/types.ts`, confirmed
  The clean tile result that the engine, the editor, the stage, the CLI and the export share. Contract: `{ cols: number; rows: number; pixels: Uint32Array }`, one packed color per tile ([[PRIMITIVES#color]]), row-major.
  Consumers: 15 (`cells.ts`, `palette.ts`, `sprite.ts`, `pipeline.ts`, `protocol.ts`, `worker.ts`; `engine.ts`, `edit-session.ts`, `state.svelte.ts`, `image-set.svelte.ts`; `cli/operations.ts`, `cli/process.ts`; `clean-scene.ts`, `set-scene.ts`, `sprite-thumb.ts`).
- **`floodRegion` / `borderBackground` / `indicesOfColor` / `listPalette` / `lineTiles` / `spriteToRaster` / `spriteFromRaster`**, `src/core/sprite.ts`, confirmed
  Tile-level operations on a `Sprite`: region and color selection, background detection, lines, palette listing and raster conversion. Contract: `floodRegion(sprite: Sprite, start: number): { indices: Int32Array; distance: Uint16Array }` (4-connected on the exact color, `distance` in steps, empty for an invalid start), `borderBackground(sprite: Sprite): Int32Array` (sorted; empty when half or more of the border is transparent or no border color has enough share; several border colors flood together, for a fake checkerboard), `indicesOfColor(pixels: Uint32Array, color: number): Int32Array`, `listPalette(pixels: Uint32Array): Array<{ color: number; count: number }>` (no `TRANSPARENT`, count desc, then value asc), `lineTiles(x0: number, y0: number, x1: number, y1: number): Int32Array` (flat x,y pairs, both ends included), `spriteToRaster(sprite: Sprite): RasterImage` (one pixel per tile, no scale; `TRANSPARENT` becomes 0,0,0,0), `spriteFromRaster(image: RasterImage, blockSize = 1): Sprite` (block center, alpha below 128 becomes `TRANSPARENT`). The export at 1x goes through `exportSprite` in `src/core/pipeline.ts`, which checks the export limit before `spriteToRaster`. `src/cli/files.ts` repeats the `spriteFromRaster` alpha rule inline.
  Consumers: 9 (`palette.ts`, `pipeline.ts`, `edit-session.ts`, `image-set.svelte.ts`, `CleanScreen.svelte`, `cli/operations.ts`, `cli/process.ts`, `cli/files.ts`, `cli/edit.ts`).
- **`resampleSprite` / `heightStep` / `resampledSize` / `wholeHeights` / `heightLimit` / `trimSprite`**, `src/core/sprite.ts`, confirmed
  Puts one clean object on a coarser or finer tile grid with an area vote, the single resize rule of the app and the CLI. Contract: `trimSprite(sprite: Sprite): Sprite` (a copy cropped to the box of the opaque tiles; `CoreError('empty-image')` when no tile is opaque); `heightStep(rows: number, height: number): number` (source tiles per result tile: 1 for the native height, a whole k up to `PARAMS.sizing.maxReduction` when `ceil(rows / k)` gives the height, 1/k when the height is a whole multiple of `rows`, otherwise `rows / height`; no upper limit); `resampledSize(cols: number, rows: number, step: number): { cols: number; rows: number }`; `heightLimit(cols: number, rows: number): number` (the largest height, at least 1 and at most `rows * PARAMS.sizing.maxEnlargement`, whose result stays inside `PARAMS.limits.maxExportSide` and `PARAMS.limits.maxCells`); `wholeHeights(rows: number, limit: number): Array<{ height: number; step: number }>` (the native height first, also above `limit`, then the 1/k reductions without a repeated height, then the k-times enlargements, each of these at most `limit`); `resampleSprite(sprite: Sprite, step: number): Sprite` (a step below 1 enlarges). In `resampleSprite`, the area outside the sprite counts as transparent; a result tile is `TRANSPARENT` when its transparent share is above `PARAMS.sizing.clearAbove`, otherwise the color with the largest area wins, and equal areas go to the darker color, then to the lower packed value; rows anchor at the bottom, columns are centered, and with a whole step each source tile falls in one result tile. `resampleSprite` throws `CoreError('too-large')` above the same limits as `heightLimit`; a step that is not finite and above 0, or a side that is not a whole number of 1 or more, gives `CoreError('internal')`.
  Consumers: 3 (`cli/operations.ts` `heightLimit`, `heightStep`, `resampleSprite`, `trimSprite`; `cli/process.ts` `trimSprite`, `wholeHeights`, `heightLimit`; `image-set.svelte.ts` all six).
- **`EditSession`**, `src/app/edit-session.ts`, confirmed
